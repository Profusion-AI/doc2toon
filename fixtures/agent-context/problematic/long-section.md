# Long Section Fixture

## Always-On Review Procedure

Before converting an agent instruction file, read the purpose, identify the intended user, check whether the document is meant to guide every task or only a narrow workflow, confirm the supported input type, decide whether the document should remain in Markdown or become TOON, compare the amount of repeated structure against the amount of ordinary prose, inspect headings for overloaded topics, inspect list items for repeated rules, inspect vague instructions for missing actions, inspect examples for redundant phrasing, inspect privacy notes for accidental storage claims, inspect testing notes for missing validation, inspect command examples for unsupported flags, inspect budget-mode claims for overstatement, inspect output language for universal savings claims, inspect the final recommendation for whether it preserves human judgment, and then produce a concise advisory report. If the section also describes how to rewrite the document, how to split the document into skills, how to run release checks, how to update docs, how to write examples, and how to prepare a UI copy deck, move those procedures into separate task-triggered files instead of keeping every step in the always-on prompt.

- The reviewer must identify the source document purpose before conversion.
- The reviewer must identify whether the file is always-on context or an on-demand procedure.
- The reviewer must check whether supported input claims match the current CLI.
- The reviewer must inspect repeated rules before recommending any rewrite.
- The reviewer must inspect vague instructions before converting the document.
- The reviewer must check long sections for mixed concerns.
- The reviewer must check whether procedural detail should move into a skill.
- The reviewer must verify that measured savings are not overstated.
- The reviewer must verify that lossy budget output is labeled clearly.
- The reviewer must confirm source document bodies are not logged.
- The reviewer must confirm examples are realistic and not filler.
- The reviewer must confirm validation commands are current.
- The reviewer must report warnings as advisory signals instead of judgments.
- The reviewer must preserve human judgment about which nuance matters.

## Short Rule

- The converter must report measured savings.
