# Realistic agent-context fixtures

Real-scale, real-shaped calibration fixtures for the verdict contract (`docs/verdict-schema-v1.md`). All content is original and describes fictional projects. Unlike the toy fixtures one directory up (12–74 lines), these are 350–840 lines and messy the way real files are messy. They were authored against the live CLI: every number below is measured, not aspirational.

Expected verdicts follow the v1 decision policy in default (lossless) mode. Measured 2026-06-10 on the calibrated verdict engine against the LF-pinned corpus (`.gitattributes` — character counts are decision inputs, so the corpus line endings are part of the contract; see `docs/calibration-v1.md`). The snapshot tests in `test/verdict.test.ts` pin these exact verdicts, so this table and the snapshots can only drift together.

## What these fixtures taught us (day-1 findings → calibration outcomes)

These drove the threshold calibration; each finding's resolution is recorded in the answered open questions in `docs/verdict-schema-v1.md` and the table in `docs/calibration-v1.md`:

1. **`convert` was unreachable for realistic agent docs — and for them, that is the honest answer.** Real CLAUDE/AGENTS/SKILL shapes profile as `mixed` (tables + rules + defs + prose ≥ 3 active kinds), and the mixed canonical duplicates section bodies into defs/rules/rows — heavily negative savings in *both* modes (record short-circuits to the same canonical). Their verdict is `keep_markdown` or `split_first`, which is the product's actual advice. `convert` is now reachable where it should be: uniform-table docs (this corpus) and clean definition sets (record mode, coverage-verified).
2. **`review` was near-unreachable; the coverage check made it the honest landing zone** for record-mode runs that win big by dropping content (finding 3).
3. **The record-mode content-loss bug, demonstrated and now contained** (`architecture-rfc.md`): the doc profiles as `requirements`, and `--mode record` reports **+91.6% savings** while the decoded output retains ~8% of the source's content characters (`extractRules` splits on newlines before sentence boundaries, so the retained fragments are cut mid-sentence). Day 1 this earned `convert` with `lossless: true` and zero warnings — the dishonest outcome decision 12 exists to prevent. Now: a `low_coverage` warning (severity `warning`) fires below 70% measured coverage and the verdict lands on `review`; `safe_to_auto_apply` additionally requires lossless mode. The `extractRules` sentence-boundary fix itself is deferred to a post-freeze minor — disclosed, no longer dangerous.
4. **Even lossless-claimed table conversion drops content** (`config-reference.md`): title, intro paragraph, and blockquote captions — measured at 9% of content characters — are silently absent while the engine reports `lossless: true`. Quantified by the coverage measurement (91%, above the warning bar), documented as the known v1 limitation; the proper fix (the `table` canonical carrying title/captions) is a post-freeze canonical change, after which coverage reaches ~100%.
5. **`long_section` fired on uniform tables — now exempt** (`config-reference.md`): the `table` profile requires ≤1 heading, so any real-size table doc is one giant "section" and long_section always fired, turning a decode-verified +22% win into `split_first`. Calibration: sections whose non-empty lines are ≥60% table rows are exempt (`LONG_SECTION_TABLE_LINE_RATIO`); the win class is reachable, and mixed-content long sections still fire.
6. **The parser's inline-definition heuristic produces junk definitions** (`SKILL.md`, `architecture-rfc.md`): capitalized lines containing a hyphen or `Term: def` shapes get extracted as definitions, inflating activeKinds toward `mixed` and (in the RFC's case) requiring deliberate line-wrapping to dodge phantom matches. Deferred to a post-freeze minor with the blast radius measured: on this corpus the phantoms change no verdict (mixed docs are heavily negative with or without them).
7. **A savings band exists because of this corpus** (`architecture-rfc.md`): on a CRLF checkout the RFC measured +0.4% and briefly earned `convert` with `safe_to_auto_apply: true` — a wrong-and-confident verdict on what turned out to be line-ending noise (the LF truth is −1.5%). `MIN_CONVERT_SAVINGS_PCT` (5%) keeps near-zero "wins" at `keep_markdown`; `glossary.md` record mode (+4.7%) is the corpus's standing sub-band case.

## Per-fixture notes

- **`CLAUDE.md`** — fictional B2B invoicing TypeScript monorepo. Reads like 8 months of accretion: a deliberately overlong Testing section (3,069 chars / 50 lines / 14 bullets vs. thresholds 1500/40/12), two near-duplicate rule pairs stated in different sections, two vague rules, plus plenty of legitimate content.
- **`AGENTS.md`** — fictional Python event-ingestion/warehouse service. Duplicates: the schema-stubs rule (Do + Schema management) and the never-point-at-prod-warehouse rule (Operating rules + Merge semantics). Vague: "Handle errors gracefully…", "Use good judgment…". All sections under the long_section thresholds, so the warnings present are exactly the review-class ones the precedence test needs.
- **`SKILL.md`** — fictional quarterly-board-report skill. Zero optimizer warnings by construction; the `mixed` profile comes from its 17 table rows + 12 extracted rules + 17 (mostly phantom) definitions. Decode check: all 38 sections/rules/defs/rows survive — no content loss on the mixed path.
- **`architecture-rfc.md`** — fictional cron-to-event-streaming migration RFC, 838 lines of prose. Enough headings to keep every section under the long_section thresholds; deliberately line-wrapped to avoid phantom definitions. The record-mode bug demonstration case (finding 3).
- **`config-reference.md`** — fictional IaC tool reference: single H1, blockquote captions, 28 uniform-schema tables, 294 rows, zero rules/defs. The legitimate-win case (decode-verified) and the long_section-vs-tables threshold case (finding 5).
